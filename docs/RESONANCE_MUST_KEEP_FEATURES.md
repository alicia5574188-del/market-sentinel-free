# Resonance 必须保留功能基线

本文件是所有后续 UI、策略、架构和品牌重构的永久回归基线。

目标不是冻结界面，而是确保已经验证且用户依赖的必要能力不会因为“简化页面”“重做产品层”或策略升级而消失。

## 1. 稳定性优先原则

恢复或保留功能时，不得重新引入页面黑屏、频繁 503、前台 Gate 扇出、接口互相拖累等旧问题。

必须遵守：

- 后台 MarketScanner 继续作为生产市场数据的权威生产者；普通页面读取不能重新变成 Gate 全市场计算生产者。
- 辅助功能接口失败只能局部降级，不能让主页面、Scanner、Position Monitor、Live Coordinator 或交易执行失效。
- 账户、通知、安全审计、复盘详情等操作型功能优先按需读取，不得仅为展示它们新增高频定时轮询。
- Mutation 不得自动重试；实盘写操作继续由既有安全边界负责。
- PWA / Service Worker 不得用缓存 App Shell 冒充 API JSON。
- 不为了恢复 UI 功能修改策略权威、风险规则、D1 历史或 Gate 凭据。

## 2. 必须保留的操作能力

### 模拟账户

- 当前模拟本金、权益、已用保证金、可用资金可见。
- 可重新开始模拟资金曲线 / 重置模拟本金。
- 重置时不得删除历史交易与学习数据。
- 有模拟持仓时不得重置资金 epoch。

### 模拟交易与复盘

- 方向、进场、当前/出场价格。
- 原始止损与当前保护价。
- TP1、TP2、TP1 是否已经触发。
- 杠杆、隔离保证金、名义仓位、计划风险。
- 成本后的 TP2 预计收益。
- MFE / MAE、退出效率、退出后观察与反事实复盘。
- 交易策略/打法、进入理由、退出理由。

### Gate 实盘

- Gate API 是否已配置、是否验证成功、错误原因。
- 凭据可以安全更换和删除；Secret 不回显。
- Auto Live 总开关。
- 立即对账。
- 风险锁 / 实盘资格及原因。
- 活动真实订单及策略解释。
- 杠杆、保证金模式、保护状态、止损/止盈。
- Emergency Stop 必须始终存在，且移动端长按不能被文本选择/系统菜单破坏。
- 实盘安全审计可查看。

### 账户

- 当前登录账户、邮箱、Owner / 只读成员身份可见。
- 退出登录入口必须存在。

### Web Push

- 开启通知。
- 关闭通知。
- 测试推送链路。
- 推送操作失败不得影响主页面。
- iPhone 仍遵循 Safari 添加到主屏幕后的 PWA 推送能力。

### 后台与诊断

- Scanner 状态、最近成功时间、阶段/错误/新鲜度等必要运行信息可诊断。
- Position Monitor / Trade Manager 状态可见。
- 页面关闭或 iPhone 锁屏后，服务器后台扫描与持仓保护继续运行。

### 导航与可发现性

- 核心控制不能只因为 UI 变简洁就完全隐藏。
- Settings / 账户 / 通知 / 实盘安全操作必须有明显可达入口。
- iPhone 底部导航与 PWA 行为不得回归。

## 3. 可以改，但不能消失

以下内容允许重新排版、折叠或迁移位置，但能力本身不得消失：

- 模拟资金重置。
- Gate 凭据管理。
- Auto Live、Reconcile、Emergency Stop。
- Web Push 管理。
- 账户和退出登录。
- 实盘风险与安全审计。
- 订单核心经济参数和 MFE/MAE 复盘。
- Scanner / Position 运行诊断。

## 4. 后续更新的强制检查

任何影响 `app/page.tsx`、主导航、设置页、交易页、实盘页、PWA 或产品架构的 PR，在完成前必须回答：

1. 新功能是否正常？
2. 本文件中的 Must-Keep 功能是否仍然可达？
3. 是否新增了不必要的轮询或 Gate 前台请求？
4. 任一辅助接口失败时是否仍能保持主页面可用？
5. Emergency Stop、Auto Live、保护与风控是否仍保持原有安全边界？
6. 是否跑过 feature-preservation / UI / build / risk regression tests？

如果 Must-Keep 回归测试失败，该更新不得视为完成。
