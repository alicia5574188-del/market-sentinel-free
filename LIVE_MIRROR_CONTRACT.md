# Permanent current-PAPER / owner-LIVE contract

Effective 2026-09-17. This requirement applies to EVERY strategy and UI release unless the owner explicitly changes it. It supersedes prior notes prohibiting the generated-rule LIVE bridge. The simulator remains a pure strategy authority with no keys; a separately owner-controlled execution adapter consumes its persisted orders.

## Required invariants

1. The current visible PAPER account is the only NEW LIVE source. Do not keep LIVE connected to a retired canonical/netted strategy while displaying a new PAPER version. Preserve the exact original source trade ID, full deep-copied order/rule information including future extension fields, original source times and price levels. Never recalculate a second strategy or relabel a different source as the original. Old already-owned live exposure drains its original lifecycle only.
2. Copy all currently OPEN, still-valid source orders after the owner enables and future orders as they appear. CLOSED history is never reopened. The current PAPER engine has at most one holding per symbol. The adapter preserves each such parent, not a net aggregation. A future multi-leg-per-symbol design MUST also deliver an identity-preserving execution adapter and tests before release; unsupported source shapes fail explicitly, never silently merge or drop parents.
3. At first copy reservation, freeze the ratio of actual marked Gate equity to contemporaneous marked PAPER equity. Target notional and margin scale by that ratio, requested leverage stays the source leverage. No 10000-display balance or old equity is used. Existing copied quantities are not resized merely because equity changes. Gate classic total is cash balance; marked equity adds unrealised_pnl. Unified collateral without an equity adapter is explicitly blocked, never auto-converted.
4. Gate lots/ticks, actual bid/ask, fills/partial fills/rejections, fees, funding and timestamps are exchange facts, NOT copied model outcomes. Size rounds down, never up to a minimum lot. Source leverage cannot be silently increased to force a fill. Insufficient available margin or valid source/quote produces a per-parent reason, not a success entry. Target vs actual/rounding/partial deviations are visible. No promise of identical actual exchange fills, fees, returns or millisecond times.
5. Source stop and protection/exit rule snapshot remain authoritative. The source arm price is NOT a take-profit command. Source closure triggers the corresponding actual close request; source deadline is not restarted at LIVE enable. Native reduce-only protection remains; an exchange-triggered protective stop, forced liquidation, operator action or unavailable API can cause differences which must be reported, not erased. Do not close merely because a current-source lookup is missing. Bound source closures persist beyond the hot PAPER history while Gate is unavailable.
6. Only the authenticated same-origin owner endpoint may change requestedEnabled. Login, API save, page navigation, deployment, optimizer, error recovery and tests do not enable LIVE. Persist the owner choice separately from older checkpoints. OFF cancels system ENTRY orders and prevents in-flight later submissions, but existing positions retain native stops and follow the original source close; OFF does not silently flatten them or delete protection. Errors can pause operational execution, not rewrite owner intent. No funds transfers, withdrawal permissions or private key disclosure.
7. Persist the full source binding and reservation atomically BEFORE a market submission. After a request may have crossed the network, an absent response is not permission to replay the same parent. Zero fills are not positions; partial fills are actual exposure with an explicit deviation. Recovery adopts previously reserved exposure, including fills that arrive after OFF or source close, protects them and follows the original parent. Persist actual close records separately from replaceable per-symbol hot state; never fabricate an unknown exit price or PnL from PAPER.
8. Every update runs `npm run test:live-parity`, `npm run test:direct`, `npm test`, typecheck, lint and build/dry-run. Parity tests exercise the actual Worker with an injected fake Gate; public network calls are forbidden in those tests. Production release/monitor must expose current source version, source count, owner-only control and connection status. Preserve PAPER strategy/account/losses/history and credentials through this adapter release. No real Gate on/off or trade is performed by the implementation session.

## Implementation and durable data

`lib/live-parity.ts` declares `current-paper-live-parity-v1` / `CURRENT_FORWARD_ACCOUNT`; it is independent of current PAPER algorithm IDs. The Worker invokes `forwardMirrorSources` for additions and `buildProportionalMirror` for sizing. Full source bindings are in `live-parity:v1:binding:<sourceId>`, matched immutable closes in `live-parity:v1:closed:...`, authoritative source exits in `live-parity:v1:source-close:<sourceId>`, and owner intent in `live-parity:v1:owner-intent`. The original forward schema and pure engine policy are unchanged. Existing `liveEligible:false` in historical/PAPER objects means those objects cannot self-authorize; runtime `liveMirror` explicitly states owner-enabled bridge capability.

Public health/runtime expose coverage metadata, never key material. Full source-to-live mapping is `/api/live/source?id=...` behind the existing owner session. Actual prices/times not verified are shown as unknown. No extra per-tick D1 writes. A bounded extra KV write occurs per new copy reservation, order checkpoint and bound source close, consuming the existing write budget. Budget exhaustion fails new entry before a Gate request; original native protection remains exchange-side. High turnover still requires monitoring actual resource use.

## Known execution boundaries, not hidden promises

Same risk caps are checked against actual available margin/current fill assumptions before copying; a source can be unexecutable on a small live account. Historical fills cannot be recovered at their past price. Maximum two new private entries are staged per sync to bound request bursts, not a two-position strategy cap; subsequent passes consume the remaining current source set. Real Gate acceptance/fills cannot be established by a fake test or a public health check. No successful real-money end-to-end trade is claimed before the owner independently enables.
