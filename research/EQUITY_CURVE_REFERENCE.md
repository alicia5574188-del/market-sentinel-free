# Observed equity curve and manual LIVE reference

## Authorized scope

User requests an original1,000USDT smooth/slidable week equity chart and a generated sentence about when to consider manually enabling LIVE, while preserving stable strategies, cadence, trading, accounts and membership. This is a READ-ONLY chart/reference release. It does not add an automatic switch, entry veto, liquidation, drawdown cap, sizing adjustment, signal source, native stop or financial reset. The source generator remains participation-execution-v1.2 and new-order exit policy timely-protection-v1. Primary/member enable fences and original position snapshots remain unchanged.

## Actual history, no fabricated earlier equity

The old chart joins the original balance and daily endpoints, concealing intraday movements. Existing immutable forward archives already contain marked day endpoints at individual data cycles. The new authenticated GET /api/forward/equity projects those saved endpoints without modifying forward state or its storage writer. A packet qualifies only when its account identity matches, daily.lastAt equals packet.at, its net equity is finite, and all open-position quotes were fresh at the time. Event-only copies of a prior endpoint and split bodies without the header do not create observations. Current runtime equity is separately labeled current valuation and never enters the historical reference.

The exact original initialEquity at startedAt is the origin. No missing history is replaced with a flat1,000line; closed-PnL totals, extrema and later market candles are not used to invent past floating equity. The line breaks when observations are more than15minutes apart. It is not a tick-level drawdown reconstruction; peaks between sampled points can be absent. Original account maxDrawdown metric remains displayed unchanged. Drawn monotone cubic segments pass through every supplied point without adding extrema between them. Tooltips snap to original saved observations. Smoothing never alters money, peak calculations or reference inputs.

The default view is7days, showing only actual elapsed history when younger;24hours and all-history controls are included. Horizontal native touch scrolling, older/newer/latest and original-start buttons, fixed initial-equity baseline and observed viewport extrema support mobile use. Older archives are loaded on demand. Long histories use a bounded20000pixel canvas; the displayed span can consequently be wider than7days on extremely old accounts rather than allocating an unbounded SVG. This cap does not remove underlying observations or change the reference's7day sample scope.

## Bounded reads, no extra trading writes

EquityReader uses one storage.list operation per uncached request, reads at most65entries, returns64 and an exact exclusive next cursor. Cache holds at most64projected pages and no raw packet bodies; current-page cache lifetime30seconds. Concurrent identical reads share a promise; different reads are refused as busy rather than queued with many raw buffers. New uncached reads are spaced at least500ms. It does not write storage, schedule alarms, access Gate, or call source advancement. A chart reader failure produces an endpoint error without changing runtime/owner/source state. Read overhead still exists: this is bounded extra dashboard work, not a claim of zero CPU or unlimited resource capacity.

The browser starts with recent observations, reads up to32pages per batch with700ms spacing, yields30seconds between unfinished batches and updates the latest page once/minute only while visible. Selecting all may request more existing history; selecting24hours does not change the reference's7day lookback. Page cursors, including zero-observation pages, are tracked independently of point count. Requests are aborted on unmount. Owner and authorized members share only the existing PAPER equity source; guests remain401. No private member balance, Gate PnL, API key or execution state is exposed by the new route.

## Reference: descriptive and conditional, not proven market timing

A pure client-side function receives unsmoothed saved marks only. It uses the latest uninterrupted comparable segment within7days, after the current algorithm/exit-policy boundaries; marks containing inherited positions with older exit timing do not supply evidence for the current reference. Missing history, outdated marks, nonpositive equity and incompatible policies cannot yield an affirmative reference. The graph may legitimately show older history which is excluded from the advice.

The observation rule is predeclared, NOT selected by maximizing this account's returns: a decline of at least1% from the observed running peak, then at least0.2%rise over30minutes and recovery of at least25%of that episode's decline. Count only the first qualifying observation per peak-to-recovery episode and space observations by at least1hour. Subsequent1hour outcomes use actual past points, including losing outcomes and episodes which never recovered; unfinished outcomes remain pending rather than counted as successes. Similar-depth groups are below2%,2–5%,and5%or more. These cutoffs are explanatory heuristics, not validated optimal settings or probabilities.

A qualified reference additionally requires complete lookback retrieval, at least24hours and200comparable marks, at least6matured similarly deep episodes, positive middle outcomes in both chronological halves, at leasttwo-thirds positive outcomes, plus current sustained two-half-hour improvement and a recent current-episode signal. Sample count is episodes, not independent trades or a statistical-confidence guarantee. The sentence can state insufficient evidence, still falling, inconsistent recovery, or conditional manual consideration. A single improving curve or unusually large drawdown is never proof of an impending rebound.

Crucial attribution: this is PAPER whole-account recovery including OLD holdings. LIVE only copies orders opened AFTER each user's enable fence. Past PAPER recovery therefore is NOT the return someone could have received by enabling at its trough. The reference explicitly states this limitation and never claims a specific future clock time, expected profit, safe entry or calibrated win probability. New-order performance must still be considered separately. No result here demonstrates that this reference improves real returns.
