# Retain equity history and fetch only new archive entries

## Request and confirmed cause
The owner reports that switching tabs destroys the equity curve and restarts historical loading. The Dashboard conditionally mounts the chart. Previously its history points and exclusive older cursor lived in component state; unmount discarded both. Each remount/range-effect restarted page-one fetch, even though the underlying archive is immutable. This was not a Gate market fetch or a new trade, but repeated Worker/DO requests and archive reads are not free of resource use. Do not infer actual quota exhaustion or a billed amount from the screenshot.

## Minimal display-only correction
- One cache instance belongs to the authenticated Dashboard, above the conditionally mounted chart. Already read points and older-page progress survive tab/range changes. Only the current GET may finish after unmount; no further history requests while hidden. Logout/account identity replacement aborts and invalidates pending work.
- A bounded, optional sessionStorage copy persists verified projection tuples and both cursors within the same browser tab across reload. Namespace is authenticated owner/member ID plus original PAPER account identity/initial capital, not a key or credential. Logout clears this cache prefix. New source accounts cannot inherit old points. Storage denial/quota/corruption falls back without deleting any in-memory or server financial records. At most20,000points/2million serialized characters are persisted; larger histories remain in memory and on server, not silently truncated. Closing the browser tab, clearing its data, switching devices or unavailable local storage may require a new initial read.
- Existing authenticated GET /api/forward/equity gains `after=<exact archive key>`. Initial/older pages retain descending exclusive cursor semantics; new pages use documented ascending exclusive startAfter with65raw-entry bound/64returned. Key-based watermark advances even across event-only/split/non-equity packets. Reconnection catches up all intervening new pages, never falsely declares an incomplete delta fresh. Past points keep their recorded amounts; conflicting overlap stops projection updates and invalidates advice.
- The already-fetched runtime's lastCycleAt suppresses latest checks when the source has no new completed cycle. New checks are at most once/minute while this chart is visible. Long first load/offline catchup remains paged in batches of32 with700ms spacing/30second yields. Reader's existing shared cache/singleflight/rate caps retained. Delta pages expire like latest pages, never cached indefinitely like old immutable pages. Changing displayed range does not discard any loaded data.
- In-memory/shared state is instance-local, never a global cross-request SSR cache. Guests still cannot load program data. No automatic LIVE authority or new private-account API added. Historical marks/smoothing/7day advice conditions unchanged. A runtime snapshot older than retained history must not erase newer confirmed marks from the drawing. Advisory stays unavailable on cache errors/incomplete catchup.
