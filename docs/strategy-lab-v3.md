# 哨兵成长策略（Sentinel Growth）

本文件取代旧的“V3 策略实验室 / 四套影子策略 / 晋级候选”产品设计。

《哨兵量化原件》的归档基线保持不变；当前 main 从原件继续成长，但对用户始终只有一套量化策略：**哨兵成长策略**。

## 核心定义

- 对外只有一套策略，不再拆成 Baseline、新策略、实验策略或候选策略。
- 对内允许多个判断模块针对不同市场状态寻找机会。
- 当前内部模块包括：
  - 综合确认（原始核心逻辑）
  - 趋势回踩
  - 波动收缩突破
  - 震荡均值回归
  - 相对强弱
- 哪个模块先形成完整有效入场条件，就成为本次订单的“触发模块”。
- 所有订单统一进入 `contract_v2` 生命周期、模拟账户、策略学习、风控和 Gate 实盘候选链路。
- 不建立多套模拟账户，不建立多套订单账本，不要求策略单独晋级或再次人工批准。
- Gate 是否允许真实开仓只由用户的“自动实盘”总开关和统一安全风控决定。

## 一套订单

每一笔订单都必须记录：

- 触发模块
- LONG / SHORT
- 入场区和实际入场
- 止损
- TP1 / TP2
- 仓位与杠杆
- 为什么进场
- 支持证据
- 反证与风险
- 为什么退出
- 实际盈亏
- MFE / MAE
- 持仓时间
- 复盘经验

模拟订单统一显示在“订单”页；Gate 真实订单统一显示在“实盘”页。两者使用同一策略解释，但资金账本保持分开。

## 一套学习

所有正常 `contract_v2` 完整订单共同进入哨兵的历史统计和策略记忆，不因为触发模块不同而人为拆成几套产品。

成长的含义是：

- 保留每次完整交易结果。
- 继续统计胜率，但不把胜率当唯一目标。
- 同时关注净期望、Profit Factor、最大回撤、最大连续亏损、手续费后收益、MFE、MAE、持仓时间和市场状态。
- 后续根据足够样本优化各模块权重、条件和市场状态路由。
- 不为了增加交易次数而简单降低统一安全门槛。

## 实盘原则

只要某个内部模块满足自己的完整入场条件，并通过统一实盘前复核，它与综合确认模块具有相同的 Gate 实盘资格。

不再存在：

- “影子策略达到 50/80 笔才能实盘”
- “策略候选线”
- “策略再次人工批准”
- “独立策略实盘开关”

仍然保留且不可绕过：

- 自动实盘总开关默认关闭
- 旧信号新鲜度保护
- Gate 实时价格与实际张数复核
- 单笔权益风险限制
- 保证金限制
- TP2 净收益门槛
- 日内亏损熔断
- 交易回撤熔断（资金划转不计）
- 同时持仓和同方向仓位限制
- 连续亏损 / 近期表现保护
- Gate 止损与止盈保护单
- reduce-only、幂等恢复和异常 fail-closed

## 页面原则：精简

五个底部页面各管自己的事情：

1. **机会**：当前市场判断、触发条件、机会队列。
2. **雷达**：数据源、市场风险、宏观事件。
3. **订单**：统一模拟订单、进出场详情、复盘和总体学习结果。
4. **实盘**：Gate 账户、真实订单、策略解释、自动实盘总开关和安全控制。
5. **设置**：监测、风险、通知和账户设置。

禁止再把策略诊断大卡片全局挂到每个页面顶部，也不再建立单独“策略实验室”页面增加使用负担。

## 内部命名兼容

部分源码文件仍保留历史名称 `shadow-strategy-*`，只是为了减少一次性大规模重命名风险。其当前职责已经是“成长策略内部模块”，新产生的有效订单不再写入 `shadow_v3:*`，而是走统一 `contract_v2` 生命周期。

历史遗留的 `shadow_v3:*` 活动记录只作为旧实验痕迹清理/归档，不再形成第二套账户或第二套订单。

## 后续优化方向

未来不是继续增加更多“独立策略产品”，而是在同一成长策略内部做：

- 市场状态路由优化
- 各模块条件和权重优化
- 样本外 / walk-forward 验证
- 模块之间相关性与重复信号控制
- 流动性、波动率、手续费和滑点自适应
- 足够样本后再考虑轻量 meta-label / ensemble

所有优化都必须继续遵守《哨兵量化原件》的资金安全边界。
