# RETURN / CONTINUATION execution v1

New post-cutover intents retain the inverse lifecycle as RETURN, with per-symbol
continuation cancellation and a separately admissible CONTINUATION branch.
Old holdings drain under their existing controller. Account identity/history,
fixed1000 allocation, frozen native capital scale and manual LIVE intent remain.

Confirmation uses consecutive completed5m bars outside a frozen balanced area,
with forward progress, or a completed retest and restart beyond its extreme.
Fresh multi-source aggregate flow must support that symbol and direction.
Current entry, structural stop, known obstacle, fee-adjusted reward/risk>=1.35,
original allocation risk and native isolated-margin/contract limits govern the
new continuation. The original source exit cannot end a continuation; its own
stop, acceptance failure and causal PI/winner manager determine subsequent exit.
Book any preceding RETURN loss and every fee. No same-episode immediate flip back.

Actual PAPER fills use their own side of the executable BBO with5bp reference
fees. LIVE consumes that same durable intent and proportional contract quantity,
with actual native rounding/capacity, final-price space/risk checks, protection
and unknown-send reconciliation.5x leverage is an absolute requested target,
never halved a second time. The manual activation fence remains new-only.

One frozen source calculation maintains the separate exact old inverse control.
Reference receipts are stored separately inside existing bounded immutable
archive packets, and snapshot/export coverage keeps reference and actual orders
apart. New episode rows are capped; quote-only pressure/reasons cannot generate
a full financial commit every two seconds. No new market-data requests/timers.
The execution page displays each actual intent's recorded entry/hold/exit
reasons; prospective candidates remain labeled as reference plans.

Acceptance covers completed-bar causality, switch fees and sunk losses, loss
reductions, old-holding drain, corrupt recovery rejection, three-ledger storage,
reference archive/export isolation, restart, source equality, source-policy
migration, real Worker branch copying and unknown-close opposite-entry blocking.
Full direct/Forward/inverse-loss/LIVE/equity/member/architecture tests, build,
typecheck, lint, diff check, Wrangler dry-run and local SQLite/workerd smokes pass.

This verifies implementation, not profitability. It cannot guarantee historical
inverse returns or exact PAPER/LIVE PnL. RETURN has no independent hard loss stop;
completed confirmation can arrive late or remain unavailable. Native latency,
funding, mark-price liquidation and account capacity remain distinct facts.
