# Shared LIVE execution and account authority

The owner withdrew favorable-entry waiting because it suppresses participation.
New inverse entries use the existing shared fresh resident Gate BBO (one final
REST BBO only if it has aged beyond two seconds) for sizing and dispatch. One
market IOC replaces the favorable limit. No source-price adverse veto remains
for inverse additions. Actual fills can still differ from source/event prices;
the existing receipt records quote time/price, submission delay and real fills.
This cannot guarantee identical exchange fills, spread or future profitability.

Current marked LIVE capital divided by current source equity sizes new inverse
allocations. An old fixed scale or profitable theoretical wallet cannot veto
new copies for a 15% divergence. Final BBO repricing preserves reserved capital
and never enlarges staged contracts. Existing exchange risk, margin, metadata,
source/account/session fences and pending-exposure reservations remain required.
No old filled, unknown or confirmed-zero submitted parent is replayed; partial
fills stay actual and never receive an unverified top-up. Existing favorable
orders retain their original identity until reconciled; unsent live sources can
follow the new policy. Committed source close/reduction still has priority.

With LIVE ON, overview equity and floating are exchange-native. The simulated
account mounts the same native LIVE order component, using actual entry/exit
prices, quantities, partial fills and confirmed settlements. Missing execution
does not contribute fictional simulated profit. Unknown/stale data stays marked
as such. Pure theoretical equity/curves are absent from the LIVE ON overview.
The independent frozen source and PAPER ledgers are preserved solely as signal
and research records; folded comparisons explicitly call these source references.
LIVE OFF returns to PAPER display without financial reset or historical rewrite.

A compact observation mark persists in the existing account-scoped runtime
checkpoint. Its first actual read after this change is the disclosed baseline;
there is no retroactive fabricated curve. Account/session changes start a new
display anchor. Gate balance plus native unrealised PnL determines equity;
native history.pnl + history.fee + history.fund deltas plus floating deltas
determine trading PnL only when all fields are available. Net capital change is
separate and labeled as including transfers. Whole-account figures can include
manual trades; program order lists and turnover remain explicitly attributed.
Negative/missing/unsupported equity prevents additions without inventing a mark.

No new private/public read cadence, alarm, table, row write or trading decision
source is introduced. Owner and member checkpoints share the implementation but
not the actual data or anchor. Credentials/manual intent/activation and legacy
native protection remain unchanged. All verification uses fake exchange fixtures
or public read-only production health; reviewed-main deployment is required.

Official protocol: https://www.gate.com/docs/developers/apiv4/en/futures/
Market futures orders use price 0 / ioc. Account history is signed cash flow;
balance excludes unrealised PnL. Tests cover deposits, incomplete cash flow,
negative equity, account/session isolation, adverse fresh quotes, final repricing,
source close, unknown sends, partial fills and LIVE ON render precedence.
